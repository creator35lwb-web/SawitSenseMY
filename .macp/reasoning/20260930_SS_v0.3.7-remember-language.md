## Decision 1: What decides the opening language

- **Trigger:** D11, approved by Alton.
- **Options:**
  - (a) The phone's language only.
  - (b) The last choice only.
  - (c) The last choice, else the phone's language, else English.
- **Chosen: (c).**
- **Rejected:**
  - (a) ignores a reader who deliberately picked another language, e.g. a Chinese reader with an English phone.
  - (b) still starts every new reader in English.
- **Details:**
  - The phone's *list* of languages is scanned, not only the first. A phone set to [French, Chinese] opens in Chinese.
  - Only explicit menu choices are saved, so a reader who never chooses keeps following the phone.
  - A stored value other than `en`, `ms` or `zh` is ignored, not trusted.

## Decision 2: How to store it without a new package

- **Options:**
  - (a) `shared_preferences`: a new package, and the lockfile can't be regenerated without local Flutter (the D9 constraint).
  - (b) `package:web`: already locked, but only as a transitive dependency. Making it direct changes `pubspec.lock`.
  - (c) `dart:js_interop` / `dart:js_interop_unsafe` from the SDK, conditionally imported, with a no-op stub for the VM tests.
- **Chosen: (c).**
- **Also:** `dart:js_interop_unsafe`'s `getProperty` / `callMethod` avoid extension types. Those would need raising the pubspec SDK floor from 3.2 to 3.3.
- **Verified:**
  - `flutter analyze` reported "No issues found!", so the web-only import raised no lint.
  - All access is wrapped in try/catch, because some privacy settings make localStorage throw.
- **Privacy:** only `en`, `ms` or `zh` is stored, on the phone. It is recorded in AGENTS.md so future storage stays that small.

## Decision 3: The truncated dashboard title

- **Found:** SS captured every top bar in EN, BM and 中文 at 360 px. The dashboard title was cut off in EN ("Daily Price Dash…") and BM ("Papan Pemuka …"). The logo takes room there; the other titles fit.
- **Options:**
  - (a) Shorter BM and EN titles.
  - (b) Let titles shrink to fit on one line.
  - (c) Leave it.
- **Chosen: (b).** It is a layout fix with no wording change, so there is nothing for a native reader to re-check, and it covers future translations.
- **Rejected:**
  - (a) is a copy change needing native review.
  - (c) With D11, BM phones land on this title first.

## Closing assessment

- **The next SS inherits:** `shoot_lang.js`-style checks. They emulate a phone's language by overriding `navigator.languages`, and a fresh browser context gives each phone empty storage. With these, language behaviour can be verified end to end without a real phone.
- **Watch for:**
  - If a later feature stores anything else in the browser, the privacy line in AGENTS.md applies.
  - If a later feature needs `package:web` directly, that's a lockfile change, and it falls under the D9 constraint.
