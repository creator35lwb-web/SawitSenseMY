## Decision 1: Where to look when no approved item is left

- **Situation:** v0.3.12 was verified and the D13 cadence needs time. Nothing approved was waiting.
- **Chosen:** read each workflow's latest run annotations. They are free, and they show what GitHub is about to break.
- **Found:**
  - A Node 20 deprecation warning on every run.
  - A notice that `ubuntu-latest` becomes Ubuntu 26 from 19 Oct 2026.

## Decision 2: How far to upgrade, and how to stay safe

- **Options:**
  - (a) Pin the runner only.
  - (b) Bump the actions one major at a time.
  - (c) Pin the runner and jump each action straight to its current major, after reading the release notes of every major in between.
- **Chosen: (c).**
- **Rejected:**
  - (a) leaves the Node 20 warnings and a pile of upgrades for later.
  - (b) multiplies the PRs and checks with no added safety, once the notes have been read.
- **What the notes showed for our usage:** three changes could matter, and none bites.
  - **checkout v6** stores push credentials in a separate file. It is designed to be transparent, but it gets proved by a real scraper push after the merge.
  - **upload-pages-artifact v4** skips dotfiles. The site build has 0.
  - **github-script v9** drops `require('@actions/github')`. Our scripts use none.
- **Why test after the merge:** a scraper run on the PR branch would commit data there, and that would conflict with `main`'s 2-hourly data commits. The deploy can only run from `main` anyway.
