## Decision 1: Trigger a manual scrape instead of waiting for the schedule

- **Trigger:** After the merges, the live data had been scraped by the *old* code (05:50 UTC, before #7), so Sarawak was still wrong on the live site. The next scheduled run was hours away, and GitHub runs the schedule 4–8 hours late.
- **Chosen:** `gh workflow run scraper_cron.yml`. One run exercised every change from #6 and #7 in production:
  - the hash-locked install
  - the fixed mapping
  - the warnings check
  - the deploy dispatch
- **Why this was within the mandate:** keeping the pipeline running is SS's job under the Genesis. The run is identical to a scheduled one, and the bot, not SS, commits the data.
- **Outcome:** everything was green, and it produced the project's first bot-dispatched deploy.

## Decision 2: What "fresh" means for the badge (D1)

- **Options:**
  - (a) Age since `scraped_at`, when we last fetched.
  - (b) Age of the CPO price's market date.
  - (c) Trading-day-aware thresholds.
- **Chosen: (a)**, with the framework's thresholds unchanged, as Alton approved in D1. It matches the backend's `get_data_freshness()`, and it detects the failure that actually happened: a pipeline that stopped publishing.
- **Rejected:**
  - (b) MPOC publishes a day or two late, so the market date would read AMBER/RED on healthy weekdays.
  - (c) The thresholds are Alton's to change.
- **Mitigation for weekends showing RED:** the badge shows the age in words and the exact time, and the RED hint says "check the date" rather than "prices may have changed".
- **Forecast:** some users may read RED at weekends as "broken". If feedback says so, propose trading-day thresholds in a framework v1.2.

## Decision 3: Remove demo data rather than label it (D2)

- **Chosen:** removed entirely. Providers return null or an empty list, and the screens show an honest state.
- **Why:** labels get missed. The History tab showed synthetic prices **with no label** for over three months, and nobody noticed. The Calculator path is the dangerous one: it gave a GREEN/AMBER/RED verdict on a dealer's quote against made-up numbers.
- **What was kept:** the Calculator still works without data, because a smallholder can type Price_1% from a receipt.

## Decision 4: One PR instead of four

- **Trigger:**
  - The repo has `delete_branch_on_merge=false`, so stacked PRs wouldn't retarget.
  - Every new PR needed the flaky-test fix to pass CI.
- **Chosen:** one PR (#9) with seven focused commits: the test fix, D2, a D2 follow-up, D1, D5, D3, and the release and records.
- **Rejected:**
  - A separate test-fix PR, which would have blocked everything else until merged.
  - Cherry-picking the fix into every PR, which duplicates history.
