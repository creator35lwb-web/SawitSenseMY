## Decision 1: See the problem before touching code

- **Trigger:** Alton's report was visual and imprecise: "the logo when launch webpages is not so well fix on the display", "the graph … is not display fully".
- **Options:**
  - (a) Guess from the code.
  - (b) Drive Alton's Chrome through the extension.
  - (c) Headless screenshots with phone emulation.
- **Chosen: (c).** The extension wasn't connected. Guessing risks fixing the wrong thing, since "logo at launch" could have meant the favicon, the PWA splash, the blank page or the top bar.
- **Outcome:** the screenshots showed four concrete defects at once: a blank launch page, the logo "sticker", colliding axis labels, and a crowded last date.

## Decision 2: How to fix the logo

- **Options:**
  - (a) Keep the full logo, just bigger.
  - (b) The emblem alone on a white badge.
  - (c) A new icon design.
- **Chosen: (b).** Alton's artwork stays, and at 40 px the fruit and fronds read clearly where the wordmark cannot.
- **Rejected:** (c) is a brand decision for Alton, not SS.
- **Process:** measured the emblem and wordmark bounds on the master, verified each crop visually, and wrote the steps down as `make_icons.py` so the icons can be regenerated.

## Decision 3: How to add the launch screen

- **Options:**
  - (a) A Flutter splash package, e.g. `flutter_native_splash`.
  - (b) Plain HTML/CSS in `index.html`.
- **Chosen: (b).**
- **Rejected:** (a) needs a new package, which means regenerating the lockfile without local Flutter (the D9 problem), for a web-only need.
- **Safety:** the screen sits behind the app (`z-index: -1`), so even if Flutter's `flutter-first-frame` event never fired, the app would paint over it. The preview confirmed the event removes it.

## Mistakes caught mid-session

| Thought | Caught when | Corrected to | Lesson |
|---------|-------------|--------------|--------|
| "The whole live page is cut off on the right at phone width." | The page cut-off didn't match Alton's report (only the graph), and phone emulation showed the page fits. | Chrome clamps headless `--window-size` to about 500 px wide on Windows; use device emulation (`setViewport`, `isMobile`). | Question a screenshot that shows more broken than the user described. |
| 8% chart headroom "to keep points off the border". | CI: the axis test expected 4600–5000 and got 4600–5100 (4978 + 25 went past 5000). | 2% headroom. | Headroom multiplies into a whole gridline step; a pure function and a unit test caught it before any screenshot. |
| Preview script ran the screenshots with `execFileSync`. | Navigation timed out: the synchronous child blocked the same process's HTTP server. | `spawn` (async). | Never block the event loop of a process that is also serving. |
