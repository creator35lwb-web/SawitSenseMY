## Context

Alton merged #18 and asked: "how was our latest version performance?" #18's branch deleted itself, so D12 works.

**The full performance baseline is in `PROJECT_STATUS.md` ("Performance").** In short:

- **Speed:** measured on an emulated phone (CPU slowed 4×).
  - The launch screen appears at 0.4 s.
  - The app and prices are on screen at 15.2 s at 1.6 Mbps (Lighthouse's mobile test), or 4.8 s on good 4G.
  - The first visit downloads 2.77 MB, most of it Flutter's graphics engine (1.58 MB). Return visits take about 1 s.
- **Freshness, the weak spot (K18):**
  - GitHub started the 56 scheduled scrapes since 21 Aug a median 4.7 h late (0.6–11.8 h). They land around 13:30 and 22:00 MYT.
  - So weekday mornings show AMBER, then RED from about 10:00.
  - The first `:13` slot (1 Oct, 00:13 UTC) had not started by 02:55 UTC.
  - Right now the live data is from 30 Sep, 17:20 MYT, and the badge is RED.
- **Quality:**
  - SonarCloud's gate passes, but older code held 1 bug and 4 vulnerabilities. They are fixed in #19 (K14–K16).
  - 93 backend and 70 frontend tests pass.
- **Usage: unknown.**
  - The site has no analytics, by design.
  - The repository had 3 page views in 14 days.
  - The feedback button thanks readers but sends nothing (K17).

**#19 (v0.3.9)** contains:

- **K14:** the deploy workflow is read-only by default; only the deploy job can write to Pages.
- **K15:** the page has a `lang`, and it follows the reader's language (en / ms / zh-Hans) for screen readers.
- **K16:** the health monitor parses the failure count from `health.json` before logging it, so log lines can't be forged.
- **Left as they are, deliberately:**
  - the duplicated literal in `mpob_bepi.py` (AGENTS.md: don't refactor the math layer);
  - two `logging.exception()` smells in the Telegram and Commodities-API failure paths. A traceback there can carry the API URL, which may contain the token or key.
